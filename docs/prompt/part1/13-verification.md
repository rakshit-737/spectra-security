43.4 Fixtures are generated, never hand-edited. `spectra fixtures build --seed 0xSPECTRA` writes `tests/fixtures/scenarios/<name>/{bundle.jsonl,ground_truth.json,manifest.sha256}`. A fixture whose manifest hash does not match is a hard test failure, not a regeneration prompt. Committing a fixture without its `manifest.sha256` fails `tools/lint/fixture_guard.py`.

43.5 Coverage rules and the ban on coverage theater. Enforce all of the following mechanically:

1. Ban assertion-free tests. `tools/lint/no_theater.py` fails any Python test function with zero `assert` statements and no `pytest.raises`; equivalent checks exist for Go (`t.Error|t.Fatal|assert.` required), Rust (`assert!|assert_eq!|matches!` required) and vitest (`expect(` required).
2. Ban coverage-only exercisers. Any test whose name matches `test_.*_coverage|test_.*_smoke_import|test_all_branches` is rejected by the linter.
3. Ban blanket `# pragma: no cover`, `#[cfg(not(test))]` coverage exclusions, `/* istanbul ignore */` and `//go:build !coverage` unless the line carries a `REASON:` comment; `tools/lint/no_theater.py` prints every exclusion with its reason into `docs/testing/exclusions.md` and fails if any lacks one.
4. Mutation testing is the real gate on the kernel. Run `mutmut` on `spectra/eclipse/` and `cargo-mutants` on `crates/eclipse-kernel/`; required surviving-mutant ratio <= 10%. Mutation runs nightly, not per-PR; the score is committed to `docs/testing/mutation.json` and regressions of more than 3 points fail the nightly.
5. Coverage numbers are reported as measured, never rounded up, never aggregated across languages into a single headline number. A single "project coverage %" badge is forbidden; the README table lists per-language measured values with the commit they came from.
6. No test may assert on a number that the test itself computed by calling the code under test and then hard-coding the result without an independent derivation. Every golden number in a test must carry a comment naming its source: `# derived by hand from fixture events e17,e18; see docs/testing/derivations.md#corridor-3`.

43.6 Speed budgets. Unit tier total wall time <= 4 min per language job. Integration tier <= 12 min. E2E <= 15 min. Any single test exceeding 5 s without the `@pytest.mark.slow` (or per-language equivalent) marker fails the suite. Slow-marked tests run in the nightly only.

43.7 Negative requirements for this section:
- Do NOT mock PostgreSQL, Redis, or the Rust kernel in the integration tier. Use real services from `compose.test.yml`.
- Do NOT write tests that reach the network. The unit and integration jobs run with `SPECTRA_OFFLINE=1` and an egress-blocking network namespace; any socket attempt to a non-loopback address raises.
- Do NOT use `time.sleep` to synchronize tests. Use explicit readiness probes and deterministic clocks (`spectra.clock.FrozenClock`).
- Do NOT commit flaky tests behind retries. `pytest-rerunfailures` is not installed. A flaky test is quarantined in `tests/quarantine/` with an open issue link and does not count toward coverage.
- Do NOT assert on LLM narration text anywhere. Narration tests assert only that narration is absent from certificate bytes and that removing the LLM changes no verdict.

44. DETERMINISM, DIFFERENTIAL AND PROPERTY TESTS
============================================================

44.1 Trace hash — the definition everything else depends on. A replay run emits a canonical trace, and its hash is the identity of the run.

```
trace_hash = BLAKE3(
    canonical_json(manifest)            ||
    canonical_json(control_config)      ||
    b"\x1e" ||
    concat over steps in emission order of:
        u64_le(step_index) || u16_le(step_kind) ||
        canonical_json(step_payload_without_wallclock)
)
```

Canonical JSON: UTF-8, sorted keys, no insignificant whitespace, integers only (no floats; fixed-point millis for time), `\u` escapes uppercase. Wall-clock fields, hostnames, PIDs, absolute paths, memory addresses and iteration timings are excluded by an allow-list schema, not a deny-list; `tools/lint/trace_schema.py` fails if a new step payload field is added without a decision recorded in the allow-list.

Required test `tests/determinism/test_replay_trace_hash.py`:
1. Run each fixture scenario 5 times in one process; all 5 trace hashes equal.
2. Run once per process across 3 fresh containers; hashes equal.
3. Run with `PYTHONHASHSEED` set to 0, 1 and random; hashes equal.
4. Run with worker pool sizes 1, 4 and 16; hashes equal.
5. Run on x86-64 and on the arm64 container; hashes equal.
6. Byte-compare the emitted `cert.json` across runs; byte-identical.
7. Assert the certificate's recorded `trace_hash` equals the independently recomputed one.

44.2 Ingest idempotency. `tests/determinism/test_ingest_idempotency.py`:
- Ingest bundle B once -> snapshot `(event_count, entity_count, fact_count, graph_hash)`. Ingest B again into the same store -> the snapshot is unchanged and the ingest API reports `duplicates_suppressed == len(B)`.
- Ingest B in 7 random chunkings; final `graph_hash` identical across all chunkings.
- Ingest B interleaved with an unrelated bundle C; the projection restricted to B's incident id is identical to ingesting B alone.
- Dedupe key is `(source_id, source_sequence, content_hash)`; assert that two records agreeing on content but differing in sequence are NOT collapsed, and that a replayed identical record IS collapsed.
- Property (hypothesis): for any list of records and any permutation with duplicates injected at arbitrary positions, the resulting event set equals `set(records)`.

44.3 Order independence of reconstruction. `tests/determinism/test_order_independence.py`:
- Property: for a bundle B and any permutation π of its records, reconstruction over π(B) yields an identical entity table, identical fact set, identical hypergraph `H` (canonical hash over sorted rule instances), identical `liveness.json`, and identical ECLIPSE certificate (modulo the ingest-order field, which must not exist).
- Hypothesis strategy: `permutations_with_jitter(B, max_delay_ms)` also perturbs arrival time while preserving event timestamps; liveness must be computed from event time, never arrival time. Assert that arrival-time jitter changes nothing; assert that event-time changes DO change liveness (a guard against accidentally ignoring both).
- Rule-ordering determinism: `tests/determinism/test_rule_order_invariance.py` shuffles the rule table order and the body-literal order within each rule (both are semantically irrelevant for a monotone Horn program) and demands byte-identical `H`, byte-identical fixpoint `U`, and byte-identical corridor enumeration `Ψ`. This is the property test demanded by the ECLIPSE spec section 3.
- Delete-effect linter: `tools/lint/rules_monotone.py` parses `rules.toml` and fails on any rule declaring a retraction, negation-as-failure, or an aggregate over a non-stratified predicate. Test `test_linter_rejects_delete_effect` feeds it a deliberately bad rule and asserts rejection with the exact diagnostic code `E-RULE-NONMONOTONE`.

44.4 Haskell policy evaluator as a differential oracle. `oracle/haskell/` contains an independently written, deliberately naive implementation of (a) the control-guard semantics and (b) ECLIPSE license admissibility. It is written from the specification text, not from the Python or Rust source, and `CODEOWNERS` forbids a single PR touching both the oracle and the implementation without a `DIFFERENTIAL-JUSTIFIED:` line in the body.

Contract `tests/contract/test_python_vs_haskell_policy.py`:
- Generate random `(control_config, request)` pairs with hypothesis over the full control lattice `∏ L_k`.
- Pipe them to `oracle-policy --json` over stdin; compare `decision`, `matched_guard_id` and `blocking_atoms` against the Python control engine. Any mismatch prints both derivations and fails.
- License admissibility: generate random `(liveness.json, rule, interval)` triples; the Haskell checker's `admits :: Liveness -> Rule -> Interval -> Bool` must agree with the Rust kernel's silent-instantiation decision on 100% of 10 000 cases per run. Shrink and record any counterexample into `tests/fixtures/counterexamples/` as a permanent regression case.

Transcript the harness must be able to produce:

```
$ pytest tests/contract/test_python_vs_haskell_policy.py -q
oracle: oracle-policy 0.4.1 (ghc 9.6.4)  impl: spectra.controls 0.9.0
generated 10000 (config,request) pairs from seed 0x5EC7  ... 10000/10000 agree
generated 10000 (liveness,rule,interval) triples         ... 10000/10000 agree
mismatch corpus: 0 new, 7 replayed from tests/fixtures/counterexamples/
.                                                                      [100%]
1 passed in 38.42s
```

44.5 F# state model as the source of truth for legal transitions. `src/fsharp/Spectra.StateModel/` defines the security-state dimensions and the legal-transition relation as discriminated unions and a total function `isLegal : State -> Transition -> State -> bool`. From it, `dotnet run --project src/fsharp/Spectra.TableGen` emits the generated artifacts:

```
generated/
  transitions.json      # full legal-transition table, canonical JSON
  transitions.sql       # CHECK constraints + enum types for PostgreSQL
  transitions.py        # frozen dataclasses + LEGAL: frozenset[tuple]
  transitions.rs        # const arrays for the kernel
  transitions.sv        # localparam state encodings for the Verilog FSM
  transitions.vhd       # constants for the VHDL FSM
  transitions.sha256
```

Drift test `tests/contract/test_fsharp_table_drift.py`:
- Re-run the generator into a temp dir; every generated file must be byte-identical to the committed one, and `transitions.sha256` must match. Failure message must be `generated artifacts are stale: run 'make regen-state-model'`.
- Assert `spectra.state.LEGAL` (Python), the Rust const array, and the SQL CHECK constraint set all decode to the same relation as `transitions.json`.
- FsCheck property in `src/fsharp/Spectra.StateModel.Tests`: the transition relation is total (every `(state, transition)` pair maps to either a target or an explicit `Rejected` reason), has no unreachable state from the initial state, and has no state with no outgoing transition except the declared terminals.
- Negative: a hand-edit to `generated/transitions.py` must fail the drift test. Include `test_hand_edit_is_detected` which patches a byte in a temp copy and asserts detection.

44.6 Verilog/VHDL state-machine cross-check. `hw/verilog/session_fsm.sv` and `hw/vhdl/session_fsm.vhd` implement the session/credential dimension FSM from the same generated encodings. `tests/contract/test_rtl_vs_model.py` drives both through cocotb/iverilog and GHDL respectively with the same randomized transition sequences used against the F# model, and asserts:
- identical accept/reject per step;
- identical final state encoding;
- both RTL builds elaborate with zero warnings under `-Wall`;
- a mutation check: flipping one encoding constant in a temp copy must make the cross-check fail (proves the test is live).

```
   randomized transition stream (seed s)
              |
   +----------+----------+-----------+
   |          |          |           |
  F# model  Python    Verilog FSM  VHDL FSM
 isLegal    LEGAL set  (iverilog)   (GHDL)
   |          |          |           |
   +----------+----------+-----------+
              |
        assert all four agree, step by step
```

44.7 WASM/Rust differential. `tests/contract/test_wasm_vs_rust.py` runs the same guard-evaluation inputs through the native Rust build and the wasm32 build under wasmtime; outputs must be bit-identical, including integer overflow behavior. This exists because the frontend evaluates guards locally for preview; a divergence would let the UI show a verdict the kernel would not certify.

44.8 Metamorphic tests. Each is a property with an explicit relation, in `tests/metamorphic/`.

| Test | Transformation | Required relation | Rationale |
|---|---|---|---|
| `test_noise_invariance` | Append N synthetic events from entities disjoint from the incident, in live windows | verdict, cut `S`, corridor set `Ψ` and `trace_hash` of the proof segment unchanged | pure noise must not move a proof |
| `test_irrelevant_event_removal` | Delete an event with no `EventId` appearing in any rule instance of the derivation | chain, cut and verdict unchanged; `liveness.json` MAY change and if it does the test asserts the change is confined to that source's q99 | removing unused evidence must not rewrite the story |
| `test_relabeling_invariance` | Consistently rename all entity identifiers under a bijection | certificate identical after applying the inverse bijection; hashes differ only through the bundle hash | reconstruction must not key on identifier spelling |
| `test_timeshift_invariance` | Add a constant offset to every timestamp | verdict, cut, corridor structure unchanged; all interval endpoints shifted by exactly the offset | absolute time must not be load-bearing |
| `test_duplicate_injection` | Duplicate a random 10% of records | identical to 44.2 idempotency result | |
| `test_monotone_evidence_addition` | Add a real event that licenses an already-licensed silent instance | that silent instance becomes observed; `S_rob` must not grow; `S_rob \ S_opt` must not grow | more sight never costs more controls |
| `test_control_antitonicity` | Raise any control level | `Reach_goal` under the larger cut is a subset of `Reach_goal` under the smaller | ECLIPSE section 7 gate |
| `test_noise_cannot_create_robust` | Add noise to an UNSAFE scenario | verdict must never become ROBUST | guards against noise-driven false safety |

Each metamorphic test runs over all fixture scenarios and over the full degradation matrix rows, and reports the (scenario, completeness) pairs it covered; the count is printed and asserted non-zero so a silently empty parametrization cannot pass.

44.9 The zero-false-ROBUST invariant. Because the generator knows ground truth, `tests/determinism/test_no_false_robust.py` iterates the entire 100%→30% completeness matrix for every scenario and every tampering mode, and asserts: if the certificate says ROBUST, the ground-truth attack path is genuinely severed by the emitted cut. One violation fails the build with no override flag, no xfail, no skip marker. Also assert that every run carrying `grounding_capped`, `subset_minimal_only` or `greedy_cover` in `flags` reports a mode other than ROBUST.

44.10 Z3 is a test-only oracle. It appears in `tests/contract/test_z3_minimality.py` and nowhere in runtime dependencies; `tools/lint/no_runtime_z3.py` fails if `z3` is importable from any non-test package. The test encodes Ψ and asserts Z3 finds no model of cardinality `< |S|`, cross-checking the branch-and-bound result on every fixture with `|A| <= 64`.

44.11 Negative requirements:
- Do NOT make determinism tests tolerant. No "hashes match modulo timestamps" assertions — exclude the field from the trace instead.
- Do NOT let a differential test pass by having both sides call the same library. `tools/lint/oracle_isolation.py` asserts the Haskell oracle's dependency closure shares no first-party package with the implementation.
- Do NOT regenerate a golden certificate to make a test pass. A changed certificate requires a diff of the certificate in the PR body and a line in `docs/testing/cert-changelog.md`.
- Do NOT use randomness without a recorded seed. Every property test prints its seed; CI exports `HYPOTHESIS_SEED`, `PROPTEST_CASES` and `QUICKCHECK_SEED` into the job summary.

Rules:

47.6 Error handling rules — the ban on silent swallowing.
1. No bare `except:` and no `except Exception: pass`. `tools/lint/no_silent_except.py` fails on both; an `except` that intentionally ignores must log at `warning` with an event name and a `REASON:` comment.
2. Go: every returned error is handled or wrapped with `%w` and context; `errcheck` runs in CI with no exclusions beyond a reviewed list.
3. Rust: `unwrap`/`expect` are denied by clippy outside tests and `main`; all fallible paths return typed errors.
4. TypeScript: `no-floating-promises` and `no-empty-catch` are errors; every `catch` reports to the error boundary.
5. Every error surfaced to a client carries a stable machine code `E-<AREA>-<REASON>` documented in `docs/api/errors.md`; the human message contains no stack trace, no SQL, no file path.
6. Degradation is always visible: any run that hit a cap, a timeout, a voided license, a dead-lettered record or a partial source appears with those flags in the API response, in the certificate, and in the UI header. A degraded run may never render as a clean ROBUST result.
7. Metrics and logs record failures even when the request succeeds after a retry; the retry count is a field, never hidden.

47.7 Negative requirements:
- Do NOT emit synthetic or estimated metric values when a measurement is unavailable; omit the sample.
- Do NOT put confidence scores, probabilities or risk percentages into logs, metrics or the UI (ECLIPSE section 9).
- Do NOT log raw event payloads at `info`; only ids and counts. Raw payloads appear at `debug` behind an explicit flag and are excluded from shipped log bundles.
- Do NOT use `print`, `console.log`, `fmt.Println` or `println!` outside CLI output paths; lint-enforced.
- Do NOT downgrade an error to a warning to keep a dashboard green.
