============================================================
64. WELL-DEFINEDNESS, TIE-BREAKING AND OUTPUT ALGEBRA
============================================================

64.0 SCOPE

This section makes every headline ECLIPSE output a *function* of the hashed inputs. An output that is
not a function of the inputs — one whose value depends on solver order, branch order, hash-map
iteration, catalog file order, or which of several equally good representatives a search happened to
find first — is forbidden to appear in a certificate, in the API, in the UI, in `docs/`, in the demo
transcript, or in the paper. There is no "we pick one and it's fine" escape. Either the object has a
canonical definition given here, or it is suppressed.

OVERRIDES Part I: ECLIPSE §4E/§4F/§4G/§4H described minimum cuts, the blindness premium, the
redundancy index, residual reachability and the Pareto frontier as if each named a unique object.
None of them did. Sections 64.1–64.8 replace those definitions. Where Part I text and this section
disagree, this section wins and the Part I wording is to be deleted from the code comments, the
OpenAPI descriptions and the docs, not merely supplemented.

Definitions used throughout, and binding on every language in the repo:

| Term | Meaning fixed here |
|---|---|
| atom | threshold literal `x_{k,ℓ} ≡ [c_k ≥ ℓ]`, `ℓ ≥ 1` |
| raised control | control `c_k` with chosen level `ℓ_k ≥ 1` |
| cut | a downward-closed set of atoms, stored canonically as one `(control_id, level)` per raised control |
| cardinality of a cut | **number of raised controls**, never the number of threshold atoms |
| corridor | an enumerated clause of Ψ: a minimal set of atoms whose raising blocks one witness derivation |
| Ψ_min, Ψ_max | corridor clause databases enumerated over P_min and P_max respectively |
| r_min, r_max | minimum cut cardinality over Ψ_min, Ψ_max |

OVERRIDES Part I: cardinality is counted in raised controls. Counting threshold atoms double-counts
levels, because `x_{k,3}` entails `x_{k,1}` and `x_{k,2}`; a 3-level control would otherwise appear
to be three controls and the "minimum cut" would be minimised over the wrong quantity.


64.1 ATOM ORDER AND STABLE BIT POSITIONS

Two distinct orders exist. Confusing them is the defect that made cuts unstable. Implement both.

(1) **Canonical atom order `≺`** — used for every ordering, every tie-break, every serialisation, and
    every printed list. Defined as:

        x_{k,ℓ} ≺ x_{k',ℓ'}  iff  (bytes(control_id_k), ℓ) <lex (bytes(control_id_k'), ℓ')

    `control_id` is compared as raw UTF-8 bytes under `LC_ALL=C`, not under any locale collation.
    `control_id` is constrained by lint to `^[a-z][a-z0-9_]{2,47}$`. This order is a pure function of
    the catalog contents and is *history-independent*: inserting a new control never changes the
    relative order of two pre-existing atoms.

    OVERRIDES Part I section 22.5: the catalog schema's `control_id` pattern
    `^[a-z][a-z0-9_]{2,31}$`, enforced by `schemas/controls.schema.json`, is replaced by
    `^[a-z][a-z0-9_]{2,47}$`, which is the single authority for both the lint and the catalog
    validator. An implementer following Part I rejects at catalog compile time the longer ids this
    section's atom order and bit-lock generator accept.

(2) **Bit positions** — used only for `u64` blocker masks, mask arithmetic and hashing. Assigned from
    an append-only registry `controls/catalog-bits.lock`, never from file position:

```toml
# controls/catalog-bits.lock   -- APPEND ONLY. Generated by `make bits-lock`. Hand edits fail CI.
lock_version = 1
[[bit]] pos = 0  control_id = "session_binding"     level = 1  state = "live"
[[bit]] pos = 1  control_id = "session_binding"     level = 2  state = "live"
[[bit]] pos = 2  control_id = "egress_seg"          level = 1  state = "live"
[[bit]] pos = 3  control_id = "legacy_kerb_hardening" level = 1 state = "tombstone"  # removed 2026-03-04
[[bit]] pos = 4  control_id = "credential_rotation" level = 1  state = "live"
```

Rules, each with a build gate:

- 64.1.1 A `(control_id, level)` pair keeps its bit position forever. Removing a control sets
  `state = "tombstone"`; the position is never reused. `make bits-lock` may only append. CI fails if
  the lock file's diff against `HEAD~` contains any deletion or any change to an existing `pos`.
  OVERRIDES Part I section 22.7: deriving bit positions from `build/controls.toml`, i.e. from
  catalog file or compilation order, is replaced by assignment from the append-only
  `controls/catalog-bits.lock` registry. An implementer following Part I renumbers every existing
  bit on any catalog edit, which this rule and `make stability-cut` step 4 forbid.
- 64.1.2 Live + tombstoned positions must satisfy `max(pos) < 64`. The gate is
  `make atom-budget`, which prints live and tombstoned counts and fails at `pos == 64`. At exhaustion
  the only sanctioned action is a `lock_version = 2` epoch: a new lock file, a new
  `catalog_epoch` field in the certificate, and an explicit statement in `docs/` that certificates
  from different epochs are not comparable by mask. Silent renumbering is forbidden.
  OVERRIDES Part I section 22.2: the `E_ATOM_BUDGET` check, taken over currently declared live atoms
  only as `Σ_k m_k ≤ 64` and published as that live count in `build/controls.meta.json`, is replaced
  by a budget over live plus tombstoned positions, `max(pos) < 64`, gated by `make atom-budget`. An
  implementer following Part I accepts a catalog whose tombstoned positions have already exhausted
  the mask width, and frees those positions for reuse.
- 64.1.3 The certificate records, for every atom in the cut, all three of `control_id`, `level`,
  `bit`, and the `rank` (0-based index in `≺` over live atoms), plus `hashes.catalog_bits`. The Go
  checker recomputes `rank` from the catalog and rejects the certificate on mismatch.
- 64.1.4 **The numeric value of a `u64` mask is never a tie-break.** Mask order is the reverse-colex
  order of `≺` and is not the order this section specifies. A lint (`make lint-tiebreak`) greps the
  Rust and Go trees for comparisons of mask values inside any `cmp`, `sort_by`, `min_by`, `max_by`,
  `Less`, or `sort.Slice` closure that feeds an output path, and fails on a hit. Masks may be
  compared by `count_ones()` (cardinality bounding in the B&B) — that is allowed and is the only
  allowed mask comparison in a decision path.


64.2 CANONICAL MINIMUM CUT

OVERRIDES Part I: ECLIPSE §4E said "take a minimum-cardinality model of Ψ". Minimum-cardinality
models are generally non-unique; that instruction does not name an object. Replace with the
following, which does.

A cut is **admissible** iff (a) it hits every clause of Ψ, and (b) it is *level-minimal*: for every
raised control `c_k` with level `ℓ_k > 1`, lowering that control to `ℓ_k - 1` while holding all
others fixed leaves at least one clause of Ψ unhit. Level-minimality is a hard requirement, not a
preference; the Go checker verifies it clause-wise in `O(|Ψ|·|S|)` and rejects the certificate
otherwise.

**Comparator `cut_cmp(C1, C2)`** over canonical cuts (each a vector of `(rank, level)` sorted
ascending by `rank`):

```
fn cut_cmp(C1, C2) -> Ordering:
    1. if len(C1) != len(C2):            return len(C1).cmp(len(C2))      // fewer raised controls
    2. for (a, b) in zip(C1, C2):
           if a.rank != b.rank:          return a.rank.cmp(b.rank)        // lexicographic on ranks
    3. for (a, b) in zip(C1, C2):
           if a.level != b.level:        return a.level.cmp(b.level)      // then weakest levels
    4. return Equal                                                       // then C1 == C2
```

Worked example (illustrative, not a target). Atoms ranked `0=credential_rotation@1`,
`1=egress_seg@1`, `2=egress_seg@2`, `3=session_binding@1`. Three admissible 2-control cuts exist:
`{0,3}`, `{1,3}`, `{2,3}`. Step 2 selects `{0,3}` — the smallest first differing rank. Note that the
mask values are `0b1001 = 9`, `0b1010 = 10`, `0b1100 = 12`; the mask-minimum happens to agree here
and will not in general. Do not rely on it; do not test for it.

**Selection algorithm.** Two phases, both deterministic, both order-independent by construction:

```
fn canonical_min_cut(Psi, budget) -> (Cut, MinimalityStatus):
    (r, status) = min_cardinality(Psi, budget)   // popcount-bounded B&B, deterministic step budget
    if status == BUDGET_EXHAUSTED: return (best_subset_minimal, SUBSET)
    cut = []
    frontier = clauses(Psi)
    for rank in 0 .. n_atoms:                    // ascending in ≺, never any other order
        if len(cut) == r: break
        if feasible(Psi, cut + [rank], r):       // ∃ completion of total size r using ranks > rank
            cut.push(rank); frontier = frontier.drop_hit_by(rank)
    cut = lower_levels_while_admissible(cut, Psi) // enforces level-minimality, low ranks first
    assert hits_all(cut, Psi) and len(cut) == r
    return (cut, EXACT)
```

`feasible` is the same B&B restricted to atoms of rank > the prefix's last, with the same step
budget. Because the outer loop walks `≺` ascending and takes the first extensible atom, the result is
the `cut_cmp`-minimum admissible cut of cardinality `r`, independent of internal search order.

- 64.2.1 The B&B is bounded by a **deterministic node budget** (`solver.max_nodes` in `run.toml`),
  never by wall-clock. Budget exhaustion sets `minimality: SUBSET` and is recorded with the exact
  node count consumed. OVERRIDES Part I: ECLIPSE §6's "exact for |A| ≤ 64" is false as a
  tractability statement; 64 is a representation width. `minimality: EXACT` is earned per run by the
  solver terminating inside budget, and is never inferred from atom count.
- 64.2.2 `safety` and `minimality` are independent certificate fields. A `SUBSET` minimality never
  degrades `safety`.
  OVERRIDES Part I section 25.9: the rule that a run with any of `grounding_capped`,
  `subset_minimal_only` or `greedy_cover` set MUST NOT be presented as ROBUST — the API returning
  `mode: "OPTIMISTIC_ONLY"` with `downgraded_by: [...]` and a grey badge — is replaced by two
  independent fields, where degradation is carried by `minimality` and never rewrites `safety`. An
  implementer following Part I emits one `mode` field carrying both meanings and suppresses a
  ROBUST verdict that this section holds to be sound.
- 64.2.3 Property test `prop_cut_canonical`: for 512 seeded shuffles (illustrative, not a target) of
  clause order, atom insertion order and rule-instance order, `canonical_min_cut` returns
  byte-identical output. Failure fails the build.

**Stability gate (`make stability-cut`).** The test that proves a reported cut does not move under an
unrelated catalog edit:

1. Run fixture `F` (a held-out scenario, per §62). Record the canonical cut `C` as
   `(control_id, level)` pairs, and `hashes.controls`.
2. Apply the mutation `catalog-edit-unrelated`: append control `noop_probe_ctl` with 2 levels, whose
   blocker bit appears in **no** rule instance grounded by `F` but does appear in a rule reachable
   only from a different fixture family (inert controls are banned outright, so the probe must be
   live somewhere).
3. Regenerate `catalog-bits.lock` (append only), re-run `F`.
4. Assert: the cut's `(control_id, level)` pairs are identical; `rank` values may shift only by
   insertion of the new atoms; every pre-existing `bit` is unchanged; `r`, `|Ψ|` and every
   `corridor_id` are unchanged.
5. Apply the mutation `catalog-edit-relevant` (append a control that *does* blocker-mask a grounded
   instance of `F`) and assert the cut is **allowed** to change but that the run is still
   reproducible byte-for-byte across two re-runs.

Step 4 failing is a bug in bit assignment or in ordering, never a reason to relax the assertion.


64.3 THE BLINDNESS PREMIUM, REDEFINED

OVERRIDES Part I: ECLIPSE §4E defined the blindness premium as the set difference `S_rob \ S_opt` of
two chosen minimum cuts. That is a difference of representatives, not a property of the problem, and
it changes when the solver's branch order changes. It is hereby deleted as a definition. The premium
is redefined as a property of the corridor clause databases.

For a corridor database Ψ with minimum cut cardinality `r(Ψ)`, define two sets over raised controls
(not over atoms — a control is in the set if any of its levels qualifies):

```
NEC(Ψ)  = { c_k : r( Ψ restricted to universe A \ atoms(c_k) ) > r(Ψ) }      // in EVERY minimum cut
OCC(Ψ)  = { c_k : ∃ℓ. 1 + r( Ψ.drop_clauses_hit_by(x_{k,ℓ}) , universe A ) = r(Ψ) }  // in SOME minimum cut
```

`r(Ψ|A\atoms(c_k)) = ∞` (no admissible cut without `c_k`) counts as `> r(Ψ)`.

**BLINDNESS PREMIUM** `B := NEC(Ψ_max) \ OCC(Ψ_min)`.

In words: controls that appear in *every* cardinality-minimum cut once unobserved steps are licensed,
and in *no* cardinality-minimum cut when only observed steps are admitted. Each member carries the
license set responsible, computed as the set of `LicenseId`s appearing in the corridors of
`Ψ_max \ Ψ_min` that `c_k` hits.

- 64.3.1 **Invariance proof obligation.** `NEC` and `OCC` are defined by the *values* of optimisation
  problems, not by any argmin. Their values are determined by Ψ alone. Therefore `B` is invariant to
  solver order, branch order, atom insertion order and clause insertion order. Encode this as
  `prop_premium_invariant`: 512 seeded permutations (illustrative, not a target) of clause and atom
  insertion order must yield an identical `B`. This property test is the proof artifact; a prose
  claim of invariance without it is forbidden in `docs/`.
- 64.3.2 **Completeness precondition.** `B` is published only when `psi_min_complete == true AND
  psi_max_complete == true AND grounding_capped == false`. Otherwise the `blindness_premium` field is
  **omitted from the certificate entirely** (see 64.8). A truncated Ψ can only shrink `NEC` and grow
  `OCC`, so a capped `B` is biased in both directions and is not reportable.
- 64.3.3 **The representative delta is a different object and gets a different name.** The UI may
  show `canonical_cut(Ψ_max)` and `canonical_cut(Ψ_min)` side by side. Their set difference must be
  labelled `cut_delta_canonical` in the API, the schema and every axis label, and must carry the
  literal caption "difference between two canonical representatives; not the blindness premium". A
  banned-phrase gate fails the build if the string "blindness premium" appears within the same UI
  component, template or export as `cut_delta_canonical`.
- 64.3.4 **What `B` does NOT mean.** Register these in `docs/claims.md` as scope qualifiers and ban
  the unqualified forms: `B` is not "controls you need because you are blind" in reality; it is
  "controls forced in every minimum cut of the corridor database enumerated over the licensed
  superset program, under this rule table and this catalog". It is not a measure of how blind the
  telemetry is. It is not causal. It is not a count of anything. It does not license the sentence
  "enabling source `s` removes control `c`" unless the decisive-observation-set computation (§4G) has
  actually been run and returned `s` as sufficient for every corridor that forced `c`.
- 64.3.5 `B` is computed with `|A| + 1` additional minimum-cardinality solves per database
  (illustrative bound on work, not a target). Each solve shares the node budget; if any of them
  exhausts, `B` is omitted and `premium_suppressed_reason = "solver_budget"` is set.


64.4 RESIDUAL REACHABILITY IS A SET, NOT A NUMBER

OVERRIDES Part I: ECLIPSE §4H used "residual reachability" as a frontier axis, which implies a
magnitude. SPECTRA forbids invented scores. Residual reachability is hereby defined as a **set-valued
object** and is forbidden to be scalarised anywhere.

```rust
/// crates/eclipse-core/src/residual.rs
#[derive(Serialize, PartialEq, Eq)]
pub struct Residual {
    /// Goal atoms still derivable under this cut. Sorted by canonical atom order of the goal library.
    pub goals_derivable: Vec<GoalAtomId>,
    /// Goal atoms proven underivable under this cut.
    pub goals_severed: Vec<GoalAtomId>,
    /// Corridors of Psi left unhit by this cut, by canonical corridor id.
    pub corridors_open: Vec<CorridorId>,
    /// Program the residual was evaluated over. Residuals from different programs never compare.
    pub program: ProgramKind,            // PMin | PMax
    /// True iff `corridors_open` is exact: Psi complete and grounding uncapped.
    pub corridors_exhaustive: bool,
}
```

```go
// checker/residual.go  — independently authored, no generated code
type Residual struct {
    GoalsDerivable       []GoalAtomID `json:"goals_derivable"`
    GoalsSevered         []GoalAtomID `json:"goals_severed"`
    CorridorsOpen        []CorridorID `json:"corridors_open"`
    Program              string       `json:"program"`
    CorridorsExhaustive  bool         `json:"corridors_exhaustive"`
}
```

- 64.4.1 `CorridorId` is `blake3-128` over the canonical encoding `LEB128(len) || LEB128(rank_i)...`
  of the corridor's atom ranks in ascending `≺` order, rendered as 32 lowercase hex characters. It is
  stable across runs with the same catalog and rule table, and is the join key for every residual,
  redundancy and frontier output.
  OVERRIDES Part I section 25.7: the small integer `corridor_id` assigned as corridors are
  discovered by the hitting-set loop, and used as the key of `spectra eclipse corridors --explain
  <corridor_id>` and `GET /api/v1/eclipse/corridors` in section 25.11, is replaced by this content
  hash. An implementer following Part I emits a solver-order-dependent identifier, so the join keys
  of residual, redundancy and frontier outputs change between runs over identical inputs.
- 64.4.2 **Scalarisation ban.** There is no field named `residual_reachability`, `residual_score`,
  `residual_pct`, `coverage`, `severity`, `risk`, `confidence`, `probability`, `score`, `rating`,
  `index` (except `redundancy_index`, which is the Jaccard defined in 64.5 and is name-registered) on
  any type reachable from the certificate, the OpenAPI schema, the Postgres schema or the TypeScript
  client. `make lint-no-scores` enforces this by walking the JSON Schema, the SQL DDL and the
  generated TS types and failing on any match of
  `(?i)(score|confidence|probability|severity|risk|rating|pct|percent|ratio|weight)` outside an
  explicit allowlist file whose every entry carries a one-line justification.
- 64.4.3 The UI renders a residual as two enumerated lists plus a corridor list. It may print
  `len(goals_derivable)` **adjacent to the enumerated list it counts**, never alone, never as a
  sort key, never on an axis, never in a headline. A Playwright test asserts that the count element
  and the list element are siblings in the DOM and that the count is absent when the list is
  collapsed.
- 64.4.4 Comparison of residuals is by **set inclusion only** (a partial order). Two residuals that
  are incomparable are reported as incomparable. There is no total ranking of residuals and no
  "better/worse" string in any API response.


64.5 REDUNDANCY INDEX: COMPLETENESS PRECONDITION AND MANDATORY SUPPRESSION

OVERRIDES Part I: ECLIPSE §4F called `red(i,j)` "exact, free, scenario-scoped" while §6 permitted
corridor enumeration to be capped. Jaccard over a truncated clause database is biased, not exact. The
unconditional exactness claim is withdrawn.

Definition, unchanged in form, now with an explicit precondition:

```
red(c_i, c_j) = |{ κ ∈ Ψ : hits(c_i, κ) ∧ hits(c_j, κ) }|
              / |{ κ ∈ Ψ : hits(c_i, κ) ∨ hits(c_j, κ) }|
hits(c_k, κ)  ⟺  ∃ℓ. x_{k,ℓ} ∈ κ
```

- 64.5.1 **Precondition.** `redundancy_index` may be emitted only when *all* of:
  `psi_complete(Ψ) == true`, `grounding_capped == false`, `corridor_cap_fired == false`,
  `horizon_truncated == false`, `solver_budget_exhausted == false`. `psi_complete` is set only by the
  hitting-set loop reaching fixpoint with no cap and no budget exhaustion — never inferred, never
  defaulted to true.
- 64.5.2 **Suppression is omission.** When the precondition fails, the `redundancy_index` key is
  **absent from the JSON object**. It is not `null`, not `0`, not `-1`, not `{}`, not `"N/A"`. The
  Rust emitter uses `#[serde(skip_serializing_if = "Option::is_none")]`. The Go checker **rejects**
  any certificate in which `redundancy_index` is present while any suppressing flag is set; this is
  checker check (g), added to the list in ECLIPSE §5.
- 64.5.3 The frontend must not render an empty table, a dash, or a zero for an absent index. It
  renders the sentence "not computed: corridor enumeration incomplete (`corridor_cap_fired`)" naming
  the exact flag. Screenshot test `redundancy-suppressed.spec.ts` covers this.
- 64.5.4 The field is denominated in corridors and labelled as such in every axis and export header:
  "share of enumerated corridors, scenario-scoped". It is never described as measuring control
  similarity, control substitutability or defensive overlap in reality.
- 64.5.5 Rational, not float. `redundancy_index` serialises as `{"num": u32, "den": u32}` with
  `den > 0` and `gcd(num, den) == 1`. No floating point enters the certificate or any decision path.
  Display rounds at render time only.


64.6 P_max IS A SUPERSET OF REALIZABLE WORLDS

State this plainly in `docs/`, in `LIMITATIONS.md`, and in the OpenAPI description of the
counterexample endpoint. OVERRIDES Part I: ECLIPSE §9 asserted "ROBUST means holds for every
hypothesis the licenses admit" as if the two-fixpoint construction computed exactly that quantifier.
It does not.

The kernel computes the least fixpoint over the union of all licensed silent rule instances. Rule
instances may carry mutual-exclusion structure — a session issued by IdP A *xor* by IdP B, a file
descriptor bound to one path, a process with one parent. P_max ignores that structure. Therefore:

```
  realizable worlds  W_real   ⊆   subsets of licensed instances   ⊆   P_max closure
  ───────────────────────────────────────────────────────────────────────────────────
  Reach(P_max) ⊇ ⋃_{w ∈ W_real} Reach(w)
```

Consequences, each of which must be written in the docs in these terms:

- 64.6.1 **Conservative for ROBUST.** If the goal is unreachable under cut `S` in P_max, it is
  unreachable in every realizable world. A ROBUST verdict is therefore sound with respect to
  realizability. This direction is safe and is the only direction the safety claim rests on.
- 64.6.2 **Not sound for counterexamples.** An UNSAFE verdict, and any counterexample derivation tree
  extracted from P_max, may combine silent instances that no single consistent world realizes. The
  tree may depict an attack that could not have happened. This is the demo's climax and it must
  carry its status on screen.
  OVERRIDES Part I section 25.9: the definition of `UNSAFE` as the goal being reachable in `P_min`
  under the user's current configuration — an observed-only property — is replaced by a verdict and
  counterexample trees that may be extracted from `P_max`, a superset of realizable worlds. An
  implementer following Part I builds counterexamples from `P_min` alone, so no tree can ever be
  unrealizable and the realizability apparatus of 64.6 has nothing to run on.
- 64.6.3 **Not sound for any OPTIMISTIC artifact derived from P_max.** Blindness premium members,
  decisive observation sets and frontier points computed over Ψ_max inherit the superset semantics
  and carry `program: "PMax"` so that no consumer can forget it.

**Realizability status.** Every counterexample tree carries:

```json
"realizability": {
  "status": "REALIZABLE | UNREALIZABLE | UNDECIDED",
  "checks_run": ["exclusive_group", "functional_key", "license_window", "obligation_multiplicity"],
  "violations": [
    {"check": "exclusive_group", "group": "session_issuer", "instances": ["ri:0x2f1a", "ri:0x9c04"]}
  ],
  "undecided_reason": null
}
```

The decidable subset, which is mandatory to implement:

| Check | Declared in | Procedure | Complexity |
|---|---|---|---|
| `exclusive_group` | `rules.toml` key `exclusive_group = "<name>"` on a rule, plus `exclusive_key = [<body slots>]` | group the tree's silent instances by `(group, key binding)`; more than one distinct head in a group is a violation | `O(n log n)` |
| `functional_key` | `facts.toml` key `functional_on = [<arg positions>]` | two facts in the tree agreeing on the key positions and differing elsewhere is a violation | `O(n log n)` |
| `license_window` | `liveness.json` | every silent instance's event time lies inside its cited license interval, and the license is BLIND/SUPPRESSED for **all** `producing_sources` of its rule | `O(n)` |
| `obligation_multiplicity` | obligation axioms, field `max_witnesses` | an obligation-induced silent instance may be cited by at most `max_witnesses` observed facts | `O(n)` |

- 64.6.4 A tree passing all four checks is `REALIZABLE`. A tree failing any is `UNREALIZABLE` with the
  violations listed. A tree containing a construct outside the four checks (declared by a rule
  carrying `realizability_undecidable = true`) is `UNDECIDED` with `undecided_reason` naming the
  rule. `UNDECIDED` is never silently promoted to `REALIZABLE`.
- 64.6.5 **UI and docs requirement.** No counterexample tree may be displayed, exported, screenshotted,
  narrated by the LLM, or pasted into a paper without its status badge rendered adjacent to the tree
  root, in text, not by colour alone. A Playwright test asserts the badge's text content for each of
  the three statuses using three committed fixtures. The LLM narration layer receives the status
  string and is forbidden by golden test from narrating an `UNREALIZABLE` or `UNDECIDED` tree in the
  indicative mood; the permitted framing is registered in `docs/claims.md`.
- 64.6.6 **Demo requirement.** `make demo` uses a fixture whose counterexample is `REALIZABLE`, and the
  demo gate fails if the status is anything else — the fixture must be fixed, the badge must not be
  hidden. A second demo beat may deliberately show an `UNREALIZABLE` tree, but only with the badge
  and the spoken-line text committed in the demo script.
- 64.6.7 GHOST labelling is orthogonal and still mandatory: every silent instance renders as GHOST at
  every zoom level and in every export, and never enters any observed-event count. A `REALIZABLE`
  badge does not make a GHOST an observation.
  OVERRIDES Part I section 25.8: checker check (e)'s requirement that each redundancy witness
  re-derive the goal under `S \ {c}` from real `EventId` leaves, and section 25.11's counterexample
  endpoint returning a derivation tree with `EventId` leaves, are replaced by trees whose silent
  instances appear as GHOST leaves carrying `evidence: []`. An implementer following Part I rejects
  with exit code 4 exactly the `P_max`-derived trees this section mandates.


64.7 COST FRONTIER: NO UNIT-COST DEFAULT

OVERRIDES Part I: ECLIPSE §4H described a Pareto frontier over "(declared cost, residual
reachability)" without saying what happens when `costs.toml` is absent. Absent a user-authored costs
file, a unit-cost default silently converts cardinality into a cost curve that looks like economic
analysis. That is fabricated economics and is banned.

- 64.7.1 With no `costs.toml`: the frontier is computed over **cardinality only**. Every field, axis
  label, legend, CSV header, PNG caption and API key on that axis is named `cut_cardinality` or
  "controls raised". The words `cost`, `price`, `budget`, `spend`, `ROI`, `investment`, `$`, `USD`
  and any currency symbol are forbidden in that mode, enforced by `make lint-no-costs`, which scans
  the API schema, the TS types, the chart configuration and the export writers.
- 64.7.2 With `costs.toml` present: the axis is `declared_cost`, always rendered with the literal
  suffix "(declared by the operator, not measured by SPECTRA)" and with `hashes.costs` printed next
  to it. SPECTRA never generates, interpolates, extrapolates or defaults a cost value. A missing
  `(control, level)` entry in `costs.toml` is a hard error, not a zero.
- 64.7.3 There is no unit-cost mode, no `--assume-unit-cost` flag, no environment variable, and no
  config key that enables one. `make lint-no-costs` fails on any identifier matching
  `(?i)unit_cost|default_cost|assume_cost`.
- 64.7.4 **Frontier well-definedness.** A frontier point is `(cut, residual)`. Dominance is the
  product partial order:

  ```
  (C1, R1) ⊑ (C2, R2)  ⟺  cardinality(C1) ≤ cardinality(C2)
                        ∧  R1.goals_derivable ⊆ R2.goals_derivable
                        ∧  R1.corridors_open  ⊆ R2.corridors_open
  ```

  The frontier is the set of `⊑`-minimal points. Incomparable points are **both kept**; they are never
  collapsed by inventing a scalar to break the tie. Within one equivalence class (identical
  cardinality and identical residual sets) exactly one representative is reported, chosen by
  `cut_cmp`. Points are serialised in ascending `cut_cmp` order.
- 64.7.5 The knapsack DP is exact only over the enumerated corridors. If Ψ is incomplete, the frontier
  is emitted with `frontier_scope: "psi_relative"` and the UI prints "frontier over enumerated
  corridors only" as body text, not a tooltip. `frontier_scope: "exhaustive"` requires the same
  precondition list as 64.5.1.


64.8 THE OUTPUT ALGEBRA: PRECONDITIONS AND SUPPRESSION

One table governs every derived output. Encode it once, in `schema/certificate.v1.json`, and
generate neither type from the other: the Rust emitter and the Go checker each implement it
independently and are held equal by the differential corpus (§62).

```
                       ┌─────────────────────────────────────────────┐
  grounding_capped ────┤                                             │
  corridor_cap_fired ──┤   SUPPRESSION LATTICE                       │
  solver_budget_exh. ──┤   any flag set  ⇒  dependent field OMITTED  │
  horizon_truncated ───┤   omitted ≠ null ≠ 0 ≠ ""                   │
  er_ambiguous ────────┤                                             │
                       └───────────────┬─────────────────────────────┘
                                       │
        ┌──────────────┬───────────────┼────────────────┬──────────────────┐
        ▼              ▼               ▼                ▼                  ▼
   canonical_cut   blindness_    redundancy_index   frontier          residual
   (always, with   premium       (needs complete    (scope tag)       (always, with
    minimality     (needs both   Psi + no caps)                        exhaustive tag)
    tag)           Psi complete)
```

| Field | Emitted when | Suppressed form | Checker rule |
|---|---|---|---|
| `safety` | always | — | must be one of `ROBUST` / `OPTIMISTIC_ONLY` / `UNSAFE`, scope-bound |
| `minimality` | always | — | `EXACT` requires solver termination in budget; `SUBSET`; `UNVERIFIED` |
| `canonical_cut` | always | — | recompute `rank`, verify hits-all + level-minimal + `cut_cmp`-minimal at cardinality `r` |
| `blindness_premium` | `psi_min_complete ∧ psi_max_complete ∧ ¬grounding_capped ∧ ¬budget_exh` | key absent + `premium_suppressed_reason` | reject if present while any precondition false |
| `cut_delta_canonical` | always | — | reject if labelled or described as the blindness premium |
| `residual` | always | — | `corridors_exhaustive` must match the flags |
| `redundancy_index` | precondition 64.5.1 | key absent | reject if present while any flag set; verify Jaccard over shipped Ψ |
| `frontier` | always | — | `frontier_scope` must be `psi_relative` unless 64.5.1 holds |
| `counterexamples[].realizability` | whenever a counterexample exists | — | reject any counterexample lacking the object |
| `declared_cost` axis | `costs.toml` present and total | key absent | reject if present without `hashes.costs` |

- 64.8.1 `premium_suppressed_reason` is a closed enum:
  `grounding_capped | corridor_cap_fired | solver_budget | horizon_truncated | er_ambiguous`. Free text
  is rejected by schema.
- 64.8.2 Serialisation is canonical: keys sorted by byte order, integers as JSON numbers with no
  exponent, no floats anywhere, strings NFC-normalised, no trailing newline inside hashed content,
  and hashing over the canonical bytes. A field that is absent is absent from the hashed bytes.
- 64.8.3 A `psi_relative` minimality claim may never render as "no smaller cut exists". The permitted
  strings are registered in `docs/claims.md`: `EXACT` → "no cut raising fewer controls satisfies the
  enumerated corridors, and enumeration reached fixpoint"; `SUBSET` → "no control can be removed from
  this cut; smaller cuts were not ruled out". The Go checker rejects a certificate whose rendered
  verdict strings (carried in `render_strings`) do not match the registry for its flag combination.
  OVERRIDES Part I section 25.13: the licensed phrasing "no smaller cut exists over the declared
  control catalog" is replaced by these two registered strings, and is itself now a banned form. An
  implementer following Part I ships a sentence that omits the enumeration-fixpoint qualifier and
  the controls-versus-atoms distinction, and that the claims-registry check rejects.

64.9 GATES

| Gate | Target | Fails the build when |
|---|---|---|
| canonical cut determinism | `make prop-cut` | any seeded permutation changes the emitted cut bytes |
| tie-break lint | `make lint-tiebreak` | a mask value is compared in an output-path comparator |
| bit lock integrity | `make bits-lock-check` | lock file shows a deletion, a renumber, or `pos ≥ 64` |
| cut stability | `make stability-cut` | an unrelated catalog edit moves a reported cut |
| premium invariance | `make prop-premium` | permuted clause order changes `B` |
| suppression algebra | `make cert-algebra` | a suppressed field is present, null, or zeroed |
| no-scores lint | `make lint-no-scores` | a scalar score/confidence/severity name appears in any schema |
| no-costs lint | `make lint-no-costs` | a cost word appears while `costs.toml` is absent |
| realizability coverage | `make prop-realizability` | a counterexample is emitted without a status object |
| checker rejection corpus | `make cert-adversarial` | any malformed/forged certificate in the corpus is accepted |

Every gate above runs per-PR. None of them is nightly-only; they are cheap and they are the ones that
keep the headline objects honest.


64.10 NEGATIVE REQUIREMENTS AND FORBIDDEN CLAIMS

- Do not report any cut without its `minimality` tag. Do not print "the minimum cut" — print "a
  cardinality-minimum cut over the declared catalog, canonical representative" or, for `SUBSET`,
  "a subset-minimal cut".
  OVERRIDES Part I section 25.11: the mandated UI result header "Minimum cut {session_binding>=device,
  egress_seg>=1} — ROBUST — …" and section 25.8's checker line "OK: no cut of size 1 satisfies Psi"
  (both quoted illustratively, not as targets) are replaced by the phrasings required here and by
  64.8.3. An implementer following Part I ships literal strings that the banned-phrase gate fails.
- Do not compute `S_rob \ S_opt` and call it the blindness premium. That expression is deleted.
- Do not scalarise residual reachability. Do not add a percentage, a ratio, a normalised coverage, a
  "% of attack paths blocked", or a progress bar backed by one.
- Do not emit `redundancy_index` on a capped run. Do not substitute zero, null, a dash, or an
  "approximate" variant.
- Do not display, export or narrate a counterexample tree without its realizability status. Do not
  describe an `UNDECIDED` tree as realizable, plausible, likely or probable.
- Do not default a cost. Do not label a cardinality axis with a currency, a cost word or a budget
  word. Do not ship a flag that turns cardinality into cost.
- Do not break a tie with a `u64` mask value, a `HashMap` iteration, a file position, a thread
  completion order, or a wall-clock measurement.
- Do not claim invariance, minimality, exactness or completeness in prose that no gate in 64.9
  enforces. If the gate does not exist, the sentence does not ship.
