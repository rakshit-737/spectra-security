# Benchmarks

Status: **not started.** No benchmark has been run and no number has been measured.

## The rule this directory exists to enforce

Every quantitative claim in the README, in `docs/`, or in the paper is generated from an artifact
produced by executing real code on real inputs. No number is hand-typed into a document. A claim
whose supporting artifact is missing or stale fails the docs gate, which is itself not implemented.

## Layout

| Path | Holds | State |
| --- | --- | --- |
| `results/` | Run outputs, git-ignored, regenerated by `make benchmark` | absent |
| `manifests/` | One manifest per run: input hashes, git SHA, toolchain versions, seeds, host fingerprint | absent |
| `harness/` | The runner itself | absent |

`bench/results/` is ignored by git deliberately. Nothing committed may depend on its presence, and
no gate may read it.

## Why results are not committed

A committed result is a number nobody can reproduce. The run manifest is committed instead: it
records everything needed to regenerate the result, and a result that cannot be regenerated from
its manifest is not evidence.

## Variance protocol

Benchmarks run in the T3 weekly tier only, because the variance protocol needs a quiet runner.
Reporting requires a declared host, a repeat count, and a reported statistic with dispersion -
never a mean alone, and never a single run. Those requirements are in Part I sections 48-51 as
amended by Part II section 70. None of it is implemented.
